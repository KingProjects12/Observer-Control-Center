# GitHub Releases + уведомления об обновлениях Observer

## Как это устроено

Исходник: пользовательский архив `dynamic-island-windows-2.1.1.zip`, файлы
`Services/Updater.cs` и `MainWindow.Updates.cs`. У Atoll проверка через GitHub API (`releases/latest`),
задержка 25 секунд, повтор каждые 6 часов, UI уведомление; при установке через Inno Setup
проверяется SHA-256 и запускается setup. Наш Observer написан отдельно, сам исходник Atoll в архив не включён.

В Observer v2.0.2 Preview реализована **фоновая проверка, но не бесшумная замена EXE**:
- Запуск проверки через 25 секунд после открытия; повтор каждые 6 часов (если включено).
- Ручная кнопка `↻ ОБНОВЛЕНИЯ` в шапке и пункт `GitHub · Обновления` слева.
- Если новая версия доступна: выделенная кнопка `● НОВАЯ vX.Y.Z`, статус в мини-островке, список изменений, переход в Releases.
- `Не напоминать об этой версии`, отключение автопроверки; сохранение настроек только на локальном ПК.
- Текущая версия определяется по `AssemblyInformationalVersion`, в т.ч. `-preview.N`.
- Берём только **стабильный** `releases/latest`; черновики и prerelease не предлагаются автоматически. Разработчик может тестировать preview вручную.
- Все запросы только HTTPS к `api.github.com`, без GitHub-токенов, паролей маршрутизаторов и статистики сети.
- Проверка работает, пока приложение запущено; она **не отправляет Windows push при закрытой программе**.
- Портативный EXE не может безопасно заменить сам себя в процессе работы; поэтому уведомление предлагает открыть официальный GitHub Release. Автоустановку можно добавить позже с отдельным подписанным установщиком.

## Что сделать один раз перед публичным выпуском

1. Создать на GitHub **публичный репозиторий** (например, `your-login/observer-control-center`).
2. Загрузить туда **только проверенные исходники из этого архива**, без локальных результатов, CSV/JSON с корпоративными IP, скриншотов с паролями, внутренней документации. `.gitignore` уже настроен, но важна ручная проверка и история git.
3. Выбрать и добавить собственную лицензию (например MIT), проверить права на графику и другие сторонние материалы.
4. Убедиться, что GitHub Actions включены. Файлы `.github/workflows/windows-build.yml` и `release.yml` приложены.
5. Для публикации стабильной версии: обновить изменения, создать git-тег `v2.1.0` и отправить тег в GitHub.
6. GitHub Actions на Windows соберёт Windows `Observer.ControlCenter.exe` **с зашитым GitHub repo из `GITHUB_REPOSITORY`**, создаст `Observer.ControlCenter.exe.sha256` и опубликует Release.
7. Любой пользователь скачает EXE с вкладки Releases; при следующих запусках тот проверит новые опубликованные стабильные релизы.

**Важно:** пока это WPF preview без прямого NAT/TOP TRAFFIC API. Не называйте его полноценной заменой v1.9.1.

## Запуск / локальная сборка

На Windows 10/11 с .NET 10 SDK:

```powershell
dotnet run --project Tests/Observer.UpdateTests.csproj --configuration Release
.\Publish-SingleExe.cmd
```

Если собираете вручную и хотите встроить репозиторий до появления GitHub Actions:

```powershell
dotnet publish Observer.ControlCenter.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:PublishTrimmed=false -p:ObserverUpdateRepo=your-login/observer-control-center -o dist
```

Если репозиторий ещё не создан, откройте `↻ ОБНОВЛЕНИЯ`, введите `owner/repo`, включите проверку и сохраните. До указания реального репозитория фоновая проверка ничего не отправляет.

## Выпуск без риска для пользователей

- Не храните пароли администратора, токены API и реальные сети в репозитории, в примерах или issue.
- GitHub API для публичных релизов работает без токена, но у анонимных клиентов есть лимит запросов; 6 часов достаточно редко.
- Не включайте автоматическую установку чужих EXE без согласия и проверки подлинности; GitHub SHA-256 подтверждает целостность файла в рамках опубликованного релиза, но не заменяет подпись издателя.
- Публикуйте `CHANGELOG` и отмечайте несовместимые изменения.
- Если когда-нибудь добавите автоматическую установку, реализуйте согласие пользователя, проверку SHA-256, подпись приложения, откат и завершение активных сборов.
- Добавлено лёгкое уведомление поверх рабочего стола WPF; это не системный push и не работает, когда программа закрыта. Отдельный Windows Notifications/tray сервис не требуется для базового сценария.
