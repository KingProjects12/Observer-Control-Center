# Observer 2.0.2 — план безопасного публичного релиза

## Реализовано в этом архиве

- Независимый код GitHub Releases checker, без копирования исходников Atoll.
- Запрос к `api.github.com/repos/{owner}/{repo}/releases/latest` только по HTTPS; два режима: фоновая и ручная проверка.
- После нового стабильного релиза показываются уведомления в основном окне, в мини-островке и временная панель в области рабочего стола. Нажатие открывает окно с информацией о релизе.
- Автоматическая проверка после 25 секунд и каждые 6 часов, если программа запущена и включён режим проверки.
- Уведомление можно отложить или скрыть для конкретной версии; нет автоматического скачивания или запуска EXE.
- У официальной сборки адрес источника обновлений зашит в EXE и **не может быть переопределён** конфигурацией пользователя. В режиме локальной разработки (без зашитого owner/repo) доступна ручная настройка.
- Репозиторий у GitHub Actions берётся из `GITHUB_REPOSITORY`; SHA256 публикуется рядом с EXE.
- Предпубликационный скрипт `tools/PublicSourceAudit.ps1` выполняется в обоих Windows workflows и отклоняет часть очевидных ошибок публикации. Это не полный аудит безопасности.

## Ещё требуется для полноценного продукта

1. **Сборка и тест на Windows:** .NET 10 SDK / Visual Studio 2026; проверить `dotnet run --project Tests/Observer.UpdateTests.csproj -c Release`, `dotnet build ...` и публикацию EXE.
2. **Вернуть функции v1.9.1:** в этой WPF-ветке **пока нет** сбора NAT и TOP TRAFFIC из Keenetic API и генерации новых XLSX. Есть импорт сохранённых CSV, графики и безопасная TCP-проверка двух портов. Не заменять рабочую v1.9.1 этим preview.
3. **Исходники:** человеческая проверка всех файлов, изображений, тестов и *всей истории Git*, а не только текущей рабочей директории. Не публиковать пароли, внутреннюю сетевую адресацию объектов, NAT-дампы, приватные сертификаты и экспортированные отчёты.
4. **Лицензия:** перед названием «Open Source» выбрать и добавить юридически определённую лицензию. Публикация публичного GitHub репозитория сама по себе не даёт права на модификацию/распространение. Если использовать код Atoll, соблюсти условия MIT и copyright. Этот прототип Atoll исходники не копирует.
5. **Релиз/подпись:** предварительный билд протестировать на чистой Windows 10/11. Цифровая подпись рекомендуется, но в этом архиве её нет.
6. **Сетевые функции:** тестировать на разрешённой инфраструктуре с ограниченной частотой запросов и защитой учётных данных. Не включать управление устройствами из WAN.

## Как проверить уведомления без изменения боевого приложения

- Создать собственный **тестовый** публичный GitHub репозиторий с безопасным Release, имеющим тег новее текущей версии.
- Для preview-версии указать его `owner/repo` в разделе «GitHub · Обновления», сохранить, нажать «Проверить сейчас».
- Убедиться, что появляется всплывающая панель, строка в мини-островке и что кнопка открывает **именно этот** GitHub Releases.
- Отключить автопроверку и убедиться, что новые запросы не уходят. Проверить режим «Не напоминать об этой версии».
- При сборке уже на настоящем публичном репозитории перейти к `ObserverUpdateRepo=OWNER/REPO` (CI делает это автоматически). Он закрепит источник обновлений.

**Не публикуйте как релиз для пользователей, пока не пройдены Windows-сборка, тесты и проверка источника обновлений.**
