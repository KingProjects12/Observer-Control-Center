# Ручная проверка Observer 2.1.0
1. Обновить приложение, открыть VPN REMOTE, проверить версию. Ввести разрешённые адреса роутеров и офисную подсеть локально, не публиковать их.
2. Повторить сбор с одного ранее успешного роутера: проверить три снимка, зелёный COMPLETE, открыть старые индивидуальные CSV/XLSX.
3. Ввести 2–3 известные разрешённые адреса с одним недоступным: проверить прогресс, правильный FAILED: TIMEOUT, отсутствие ложного CANCELLED, общий отчёт. При разных логинах использовать ЛОГИН РОУТЕРА; пароль только на сессию.
4. В текущем окне нажать ПОВТОРИТЬ ПРОБЛЕМНЫЕ после восстановления доступности. Общий отчёт новой папки должен сохранить старые наблюдения и добавить новые. При отмене сохранить доступные данные; оригинальные папки не изменяются.
5. Анализ доступов: выбрать оригинальные 07_Office_To_Connections.csv из раннего сбора и дополнительного сбора (не файл статусов и не XLSX); указать целевую /24. Проверить уникальные назначения и протокол, источник → офис, аудит повторного файла и обратных/невалидных записей. Сравнить с прежним ручным анализом.
6. Проверить TCP только в разрешённой частной сети. TCP OPEN не означает нужный бизнес-сервис, TIMEOUT не означает SOCKS, UDP не проверяется TCP. Сравнить с прежним CSV проверки, учитывая время и маршрут.
7. Экспорт CSV/XLSX; открыть Office_Access_Analysis.xlsx, Office_IP_Port.csv, Office_Source_Rules.csv, Import_Audit.csv. Проверить соответствие строк, сохранение протокола и источника.
8. СРАВНИТЬ ДВА ПЕРИОДА: выбрать ранний и поздний CSV отдельно. Проверить новые, присутствующие в обоих и не наблюдаемые позднее связи. Для сравнения брать сопоставимый охват и период; не удалять правила по отсутствию наблюдения.
9. Проверить TOP Traffic с одним роутером, обновления, смену языка, тёмное оформление, поиск по IP и портам в соединениях. Не публиковать отчёты или пароли на GitHub.
